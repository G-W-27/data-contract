## 二、边界声明（写正文必须逐字保留）

### 1. 本轮已落地（第六卷 5.1 清单内，✅ 实证）

- **① 契约变更可追溯**：CCR 变更单 + B Git 环（candidate+diff 提交，`git_ref` 回填，SHA=`23421e0…`）。
- **② 人工门禁**：`requested_by ≠ approved_by` 强约束 + 后端防重复提交（A 项实证）。
- **⑥ LLM Contract Copilot**：人话 → JSON → 两道闸（Schema / 字段白名单）→ 内容寻址 `rule_id` → YAML diff → candidate；**绝不覆盖生产 YAML**，四护栏齐备。
- **⑦ 失败解释 + 跨切面审计 + 修复单 + 告警去重**：D（确定性聚类 + 一类一次缓存）、C（8字段审计 + PII脱敏）、E（SQL定位 + 固定模板，LLM不参与）、F（进程内 Set/TTL 去重）。
- **⑨ Evals 黄金集 + H CI 门禁**：18 条用例离线回放，基线偏差 0、拦下 6、缺口 5（已知天花板）；CI 退出码 0/1 兜底。

### 2. 规划 / 下一轮（🔵 不写死，不在本轮范围）

| 项 | 内容 | 规模化形态 | 为什么本轮不做 |
|---|---|---|---|
| ③ 变更审批人资格 | 审批人资质 / 冲突矩阵 | —— | 第六卷 5.1 未列入本轮需求；当前 `requested_by≠approved_by` 已满足最小门禁 |

> ③④⑤ 是同一契约主线上的更远节点，不是脱节方向；但它们依赖「大数据量 / 多团队并行」的触发条件，
> 当前仿真环境（1 万条、单契约）未触发，故标为规划，实现时按「触发条件 → 引入技术 → 选择依据 → 回到契约」的写法展开，不写愿望清单。

### 3. 已知天花板（必须写明，不粉饰）

- **结构化闸门天花板**：Evals 基线闸门缺口 5 条（06/07/08/09b/10），业务上应拒、闸门却放行。
  这不是执行器缺陷，由 Day 1 变更单（CCR → 独立审批 → Git → CI）兜底。
- **护栏④部分落地**：网页对话无法固定 `temperature` / `seed`，版本可追溯的「输入固定」在浏览器端不成立；
  代码层以 `model_version` + `prompt_version` + 输入哈希固化证据，不伪称全链路可复现。
- **定位经视图而非底层表**：E 项定位 SQL 走 `erp_transactions` 视图再 JOIN `journal_entries`，
  因视图列名 / 派生逻辑（如 `missing_support_flag` = `supporting_document_flag` 反相）与源表不一致。
