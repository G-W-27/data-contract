别担心“什么都不会”，这个项目恰恰是为初学者设计的。我们会用最简单的工具，一步步把它做出来。

你的第一步，不是写代码，而是**搞定环境和数据**。我们开始吧。

### 🛠️ 第一步：环境准备与项目初始化

在开始之前，确保你的电脑上安装了 Python（建议 3.10 或以上版本）。你提到的 PyCharm、VSCode 和 Cursor 都是很好的代码编辑器，选一个你最顺手的就行，新手推荐 **VSCode**，轻量且插件丰富。

**1. 安装 `uv` 工具（数据契约的“引擎”）**

`datacontract-cli` 是项目的核心工具，官方推荐用 `uv` 来安装。打开你的终端（Terminal）或 PowerShell，输入以下命令：
```bash
# 如果你还没有安装 uv，先用 pip 安装它
pip install uv

# 然后使用 uv 安装 datacontract-cli
uv tool install --python python3.11 'datacontract-cli[all]'
```
安装完成后，输入 `datacontract --version` 验证是否成功。

**2. 创建项目文件夹**

在你的电脑上新建一个文件夹，比如叫 `erp-data-contract`。用 VSCode 打开这个文件夹，所有后续的文件都放在这里。

**3. 初始化 Python 虚拟环境**

为了保持环境干净，我们在项目文件夹里创建一个虚拟环境。在 VSCode 的终端中运行：
```bash
python -m venv .venv
# 激活虚拟环境 (Windows)
.venv\Scripts\activate
# 激活虚拟环境 (Mac/Linux)
source .venv/bin/activate
```
激活后，终端前面会出现 `(.venv)` 的标识。

### 📊 第二步：获取并预览数据集

你已经找到了数据集，这一步的关键是把它“请”到你的项目里。

1.  **下载数据集**：访问 Kaggle 数据集页面，下载 `universal_enterprise_erp_fraud_dataset.parquet` 文件。
2.  **放入项目**：在项目根目录下，新建一个 `data` 文件夹，把下载好的 `.parquet` 文件放进去。
3.  **安装 Pandas**：在激活的虚拟环境中，安装数据分析必需的库：
    ```bash
    pip install pandas pyarrow
    ```
4.  **快速预览数据**：新建一个 `preview_data.py` 文件，输入以下代码并运行，熟悉你的“原材料”：
    ```python
    import pandas as pd

    # 读取数据
    df = pd.read_parquet('data/universal_enterprise_erp_fraud_dataset.parquet')
    
    # 查看前5行
    print(df.head())
    
    # 查看列名和数据类型
    print(df.info())
    
    # 查看数值列的统计摘要
    print(df.describe())
    ```
    运行后，观察控制台输出，**重点关注**：有哪些列（字段）、每列的数据类型（是数字、文本还是日期）、有没有明显的缺失值。

### 📜 第三步：编写你的第一份“数据契约”

这是项目的灵魂。数据契约就是一个 YAML 文件，用文字描述了你对数据的“期望”。

在项目根目录下，新建一个文件，命名为 `financial_data_contract.yaml`。我们先从一个最简单的、能跑通的版本开始：

```yaml
# financial_data_contract.yaml
dataContractSpecification: 0.9.3
id: erp-accounting-risk-contract
info:
  title: "ERP Accounting Risk Data Contract"
  version: "1.0.0"
  description: "用于验证ERP会计风险数据质量的数据契约"

# 这里我们先不连接数据库，而是直接指定本地Parquet文件路径
servers:
  local:
    type: local
    path: "data/universal_enterprise_erp_fraud_dataset.parquet"
    format: parquet

# 定义数据模型（即你的数据表结构）
models:
  erp_transactions:
    description: "ERP交易记录"
    type: table
    fields:
      # 以下字段名需要根据你实际数据集的列名进行修改！
      # 这里用示例列名，请替换成你数据集里真实的列名
      transaction_id:
        type: string
        description: "交易唯一标识"
        required: true
        unique: true
      amount:
        type: number
        description: "交易金额"
        required: true
        quality:
          - "amount >= 0"  # 金额不能为负数
      debit_credit:
        type: string
        description: "借贷标志"
        required: true
        quality:
          - "debit_credit in ('D', 'C')"  # 借贷标志只能是 D 或 C
```

> **注意**：`fields` 下面的字段名（如 `transaction_id`, `amount`）**必须**和你数据集里实际的列名完全一致。你需要根据 `preview_data.py` 的输出，把这里替换成真实的列名。

### ▶️ 第四步：运行测试，见证奇迹

现在，激动人心的时刻到了。在终端中，确保你在项目根目录下，运行：
```bash
datacontract test financial_data_contract.yaml
```

### 📁 第五步：用 Git 管理你的项目

你已经有了 GitHub 账号，这一步很简单。

1.  **初始化 Git 仓库**：在项目根目录下，运行 `git init`。
2.  **创建 `.gitignore` 文件**：在项目根目录下新建一个名为 `.gitignore` 的文件，填入以下内容，避免把数据文件和虚拟环境上传到 GitHub：
    ```
    .venv/
    data/
    __pycache__/
    *.pyc
    ```
3.  **首次提交**：
    ```bash
    git add .
    git commit -m "feat: 初始化项目，添加数据契约和预览脚本"
    ```
4.  **推送到 GitHub**：在 GitHub 上新建一个空仓库（不要初始化 README），然后按照提示将本地仓库关联并推送上去。

### 💡 后续可以做什么？

这一步完成后，你已经有了一个能跑通的 MVP（最小可行产品）。接下来，你可以继续打磨：

*   **丰富契约**：根据 `describe()` 的结果，为更多字段添加类型、必填、唯一性和业务规则（如借贷平衡）。
*   **加入流水线**：学习用 `Airflow` 或 `Kestra` 把这个测试步骤编排成定时任务。
*   **生成报告**：用 `Streamlit` 做一个简单的看板，展示每次契约测试的通过率和失败明细。
*   **连接数据库**：把数据从 Parquet 文件导入 PostgreSQL，然后在契约的 `servers` 部分配置数据库连接，体验真正的“生产级”数据契约。

在写任何数据契约之前，我们必须先知道这些数据长什么样。因为数据契约里的字段名，**必须**和数据集里真实的列名一模一样。

1. 在项目根目录下，新建一个文件，命名为 `preview_data.py`。
2. 复制以下代码进去（假设你的数据是 CSV 格式，如果是 Parquet，把 `read_csv` 换成 `read_parquet`）：

```python
import pandas as pd
import os

# 把这里替换成你真实的数据文件名
# 如果是在 data 文件夹里，路径就是 'data/你的文件名.csv'
file_path = 'data/universal_erp_accounting_risk.csv'  

# 检查文件是否存在，防止路径写错
if not os.path.exists(file_path):
    print(f"❌ 找不到文件: {file_path}")
    print("请检查：1. 文件名对不对？ 2. 是不是放在 data 文件夹里了？ 3. 后缀是 .csv 还是 .parquet？")
else:
    # 读取数据
    df = pd.read_csv(file_path) # 如果是 parquet 文件，请改成 pd.read_parquet(file_path)
    
    print("✅ 数据读取成功！")
    print("-" * 30)
    
    # 1. 看看前5行数据长什么样
    print("【前5行数据预览】:")
    print(df.head())
    print("-" * 30)
    
    # 2. 看看有多少行、多少列，以及每列的数据类型
    print("【数据总体信息】:")
    df.info()
    print("-" * 30)
    
    # 3. 看看数值列的统计摘要（最大值、最小值、平均值等）
    print("【数值列统计摘要】:")
    print(df.describe())
```

### 🔍 为什么会报这个错？
你的 Windows 是中文系统，默认编码是 `GBK`。当 `datacontract-cli` 尝试去读取你的 YAML 文件或数据文件时，它默认用 `GBK` 去解码。但是，你的文件（里面包含了中文注释，或者数据本身是 UTF-8）实际上是以 `UTF-8` 格式保存的。
`UTF-8` 的中文字符遇到 `GBK` 解码器，就像用英语的语法去读中文，直接崩溃了。

**请按以下步骤修改你的 `financial_data_contract.yaml`：**

1.  找到 `manual_entry_flag` 字段。
2.  将其 `quality` 部分替换为以下内容：

### 📜 新的语法结构解释
这个新语法会告诉 `datacontract` 执行以下逻辑：
*   **`type: library`**：声明这是一个 Library 规则。
*   **`metric: invalidValues`**：指定要检查的指标是“无效值数量”。

*   **`mustBe: 0`**：设定通过条件，即“无效值的数量必须等于 0”。

### 💡 知识扩展：其他常用 Library 规则

*   **检查空值数量**：`metric: nullValues`，配合 `mustBe: 0`，确保字段无空值。
*   **检查值范围**：`metric: invalidValues`，配合 `arguments: validValues: [...]`，限定枚举值。
*   **检查重复值**：`metric: duplicateValues`，配合 `mustBe: 0`，确保字段（如主键）唯一。
*   **检查行数**：`metric: rowCount`，配合 `mustBeGreaterThan: 0`，确保表不为空。
